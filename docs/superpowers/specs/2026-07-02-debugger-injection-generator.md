# 断点调试器注入器生成器 (BuildTimeInjector)

> 日期: 2026-07-02
> 状态: ✅ 已实现 + 测试 + 集成 (commit `5a18336c`, `af3fe75d`)
> 关联: 子项目 9 (集成) 9d 注入器扩展的细化 + 后续演进

## 背景

子项目 1-9 已经完成 6 选 1 连接方案的 IDE 端 + host 端 runtime, 子项目 9d
已经扩展 `IdeDebuggerInitScriptPlugin` 注入了 `ide-debugger-host` AAR +
Manifest placeholder。但还缺:

1. **断点位置数据模型没有暴露到 host app**:
   - IDE 端 bp 系统内部用 (sourceFile, line, column) 描述位置
   - host app 想主动注册"预热 bp"或者构造 bp 数据时, 只能手写 ByteArray
     或者直接调 JDWP 客户端库, 没有类型安全的数据类
   - "每行每列"的语义在 IDE 端和 host app 端不统一

2. **build-time 生成内容跟 IDE 端版本/配置"是否新鲜"无校验手段**:
   - 现有注入只写了一次 (ContentProvider + AAR), 没有 build-time 戳
   - IDE 端 IDE debugger 升级后, host app rebuild 时拿到的代码确实是最新,
     但**没有证据**(日志/常量) 证明

3. **host app 端没有"一键接入" 的显式 API**:
   - 子项目 9c 的 `HostAttachAgentBootstrap` (ContentProvider) 自动化了
     反连, 但 host app 开发者**没有显式的接入点**来:
       - 看 IDE 端配置 (本地服务名 / 协议版本 / build 时戳)
       - 在 Application.onCreate 里**主动**触发反连 (跟 ContentProvider 互补)
       - 构造类型安全的 bp 数据 (供后续预热 bp / 自定义事件用)

## 目标

提供 build-time **`.kt` 源文件生成器** (扩展子项目 9d 的
`IdeDebuggerInitScriptPlugin`), 在 host app build 时生成
`IdeDebuggerBootstrap.kt` 到 generated-sources 目录, 包含:

- IDE 端配置快照 (IDE_DEBUGGER_VERSION, LOCAL_SERVER_NAME,
  HELLO_PROTOCOL_EXTRA_FIELDS, BUILD_TIMESTAMP_MS)
- **bp 位置数据类型** `BreakpointLocation(sourceFile, line, column)`
- **预热 bp 列表** `PREHEAT_BREAKPOINTS` (默认空, 留扩展点)
- **显式 init API** `init(application)`, 与 ContentProvider 互补, 多次调用
  幂等

保证:
- host app rebuild 时拿到的是 IDE 端最新代码 (用 BUILD_TIMESTAMP_MS 验证)
- host app 开发者有类型安全的数据类构造 bp (BreakpointLocation)
- 生成失败不阻塞 build (logger.warn, 跟现有 placeholder 注入一致)

## 设计

### 1. 架构

```
┌──────────────────────────┐
│ IDE 端 Build Time         │
│ IdeDebuggerInitScriptPlugin.apply()
│  ├─ 注入 ide-debugger-host AAR (9d 已有)
│  ├─ 注入 Manifest placeholder (9d 已有)
│  └─ [新] 生成 IdeDebuggerBootstrap.kt   │
│       ├─ IDE_DEBUGGER_VERSION           │
│       ├─ LOCAL_SERVER_NAME              │
│       ├─ HELLO_PROTOCOL_EXTRA_FIELDS    │
│       ├─ BUILD_TIMESTAMP_MS             │
│       ├─ BreakpointLocation (data class)│
│       ├─ PREHEAT_BREAKPOINTS (空)        │
│       └─ init(application) (幂等)        │
└──────────────────────────┘
              │ writeText 到 generated-sources
              ▼
┌──────────────────────────┐
│ Host App Compile Time    │
│ Kotlin 编译器 pickup      │
│ 编出 IdeDebuggerBootstrap.class
└──────────────────────────┘
              │
              ▼
┌──────────────────────────┐
│ Host App Runtime         │
│ - ContentProvider 自动    │ (子项目 9c, 不需要 .kt)
│ - 显式 init(application)  │ (新, 开发者主动调)
│ - 两者互补, 多次调用幂等  │
└──────────────────────────┘
```

### 2. 生成产物

路径: `build/generated/source/ide_debugger/{variant.name}/kotlin/com/itsaky/androidide/zerostudio/ide/debugger/host/generated/IdeDebuggerBootstrap.kt`

内容:

```kotlin
// AUTO-GENERATED by IdeDebuggerInitScriptPlugin (sub-project 10)
// DO NOT MODIFY — Regenerated on every build from current IDE debugger version
package com.itsaky.androidide.zerostudio.ide.debugger.host.generated

import android.app.Application
import android.util.Log
import com.itsaky.androidide.zerostudio.ide.debugger.host.HostAttachAgentBootstrap
import java.util.concurrent.atomic.AtomicBoolean

object IdeDebuggerBootstrap {
    private const val TAG = "IdeDebuggerBootstrap"

    // ---- 1) IDE 端配置快照 (build-time 注入, 保证新鲜) ----

    /** IDE debugger version that generated this file (BuildInfo.VERSION_NAME) */
    const val IDE_DEBUGGER_VERSION: String = "<ide_version>"

    /** Per-project unique LocalServerSocket name (与 Manifest placeholder 同步) */
    const val LOCAL_SERVER_NAME: String = "ide-debug-bridge-<group>-<name>"

    /** HELLO 协议额外字段 (e.g. "sdk=33") */
    const val HELLO_PROTOCOL_EXTRA_FIELDS: String = "<extras>"

    /** Build 时戳 (用于日志关联, 验证"新鲜度") */
    const val BUILD_TIMESTAMP_MS: Long = <build_time_millis>

    // ---- 2) bp 位置数据类型 (host app 端类型安全构造 bp) ----

    /**
     * 断点位置: sourceFile + line + column 三元组。
     * column = 0 表示不指定列 (按整行匹配, 兼容老式 IDE)。
     * 反映 IDE 端 bp 系统的"每行每列"语义。
     */
    data class BreakpointLocation(
        val sourceFile: String,
        val line: Int,
        val column: Int = 0,
    )

    // ---- 3) 预热 bp 列表常量 (build-time 注入, 默认空, 留扩展点) ----

    /**
     * IDE 端配置的"预热 bp"列表。在 build-time 注入, host app 启动时自动
     * 装上这些 bp (省去 IDE 端每次重设的开销)。当前默认空数组; IDE 端
     * 后续可扩展 (方案 B 路径: 在 IDE project 文件配置 bp 列表, 通过
     * Gradle property 传到 plugin, plugin 写入 PREHEAT_BREAKPOINTS)。
     */
    val PREHEAT_BREAKPOINTS: List<BreakpointLocation> = emptyList()

    // ---- 4) 显式 init API (与 ContentProvider 互补) ----

    private val initialized = AtomicBoolean(false)

    /**
     * 显式 init: 与 ContentProvider 互补。多次调用幂等。
     *
     * @param application host app 的 Application 实例
     */
    @JvmStatic
    @Synchronized
    fun init(application: Application) {
        if (initialized.getAndSet(true)) return
        Log.i(TAG, "init: ideDebuggerVersion=$IDE_DEBUGGER_VERSION " +
                "localServer=$LOCAL_SERVER_NAME " +
                "extras=$HELLO_PROTOCOL_EXTRA_FIELDS " +
                "buildTs=$BUILD_TIMESTAMP_MS " +
                "preheatBpCount=${PREHEAT_BREAKPOINTS.size}")
        HostAttachAgentBootstrap.startReverseConnectThread(application, LOCAL_SERVER_NAME)
    }
}
```

### 3. 注入流程

扩展 `IdeDebuggerInitScriptPlugin.registerBootstrapProvider` (子项目 9d 已有):

在 `ext.onVariants { variant -> ... }` 里, debuggable variant 走完现有
AAR + placeholder 注入后, 新增 try 块:

```kotlin
try {
    // 1) 算生成路径
    val buildDir = project.layout.buildDirectory.asFile.get()
    val generatedDir = File(buildDir, "generated/source/ide_debugger/${variant.name}/kotlin")
    val pkgPath = "com/itsaky/androidide/zerostudio/ide/debugger/host/generated"
    val targetFile = File(generatedDir, "$pkgPath/IdeDebuggerBootstrap.kt")

    // 2) 算 build-time 注入参数
    val ideVersion = BuildInfo.VERSION_NAME
    val localServerName = computeLocalServerName(project)
    val sdkInt = project.findProperty("ideDebuggerSdkInt")?.toString() ?: "0"
    val extras = "sdk=$sdkInt"
    val buildTs = System.currentTimeMillis()
    val preheatBps = parsePreheatBreakpoints(
        project.findProperty("ideDebuggerPreheatBreakpoints")?.toString()
    )

    // 3) 渲染 + 写文件
    val content = renderIdeDebuggerBootstrapKt(
        ideVersion = ideVersion,
        localServerName = localServerName,
        extras = extras,
        buildTimestampMs = buildTs,
        preheatBreakpoints = preheatBps,
    )
    targetFile.parentFile.mkdirs()
    targetFile.writeText(content)

    // 4) 把 generatedDir 加到 Kotlin source set
    variant.sources.kotlin?.addStaticSourceDirectory(generatedDir.absolutePath)
} catch (t: Throwable) {
    logger.warn("IdeDebuggerInitScriptPlugin: failed to generate IdeDebuggerBootstrap.kt: ${t.message}")
}
```

**失败处理**: logger.warn, 不抛 (跟现有 placeholder 注入一致)。如果 host app
依赖 `IdeDebuggerBootstrap`, 编译期会因"类型找不到"而失败, 这是**显式**
反馈, 引导开发者修 build script (但不会让 host app 整个 build 失败,
  因为 IDE 端 Gradle plugin 出问题不应该让 host app 编不了)。

### 4. 关键函数

#### 4.1 `renderIdeDebuggerBootstrapKt(...)`

`internal fun renderIdeDebuggerBootstrapKt(...): String`, 纯函数, 不依赖
Gradle, 接受 5 个参数:

| 参数 | 类型 | 说明 |
|------|------|------|
| `ideVersion` | String | IDE 端版本 (BuildInfo.VERSION_NAME) |
| `localServerName` | String | per-project 唯一 LocalServerSocket 名字 |
| `extras` | String | HELLO 协议额外字段 |
| `buildTimestampMs` | Long | build 时戳 |
| `preheatBreakpoints` | List<RenderedBreakpoint> | 预热 bp 列表 |

返回**完整 .kt 源文件文本** (用字符串模板拼接, 不引入 KotlinPoet 依赖)。

**`RenderedBreakpoint(sourceFile: String, line: Int, column: Int)`** 内部数据
类, 跟生成的 `BreakpointLocation` 字段一一对应, 用于**渲染** (内部) 和
**解析** (Gradle property → 数据) 的桥梁。

**字符串转义**: 
- 5 个参数中, `localServerName` 和 `extras` 用 Kotlin 字符串字面量
  (即 `"..."` 包裹, **必须转义内部引号** `\` 和 `\\` + 换行符 `\n`)
- `ideVersion` 也走同样转义
- `preheatBreakpoints` 元素 `sourceFile` 同样转义

实现方式: 写一个 `escapeKtStringLiteral(s: String): String` 工具函数, 把
`"` 替换为 `\"`, `\` 替换为 `\\`, 换行/回车替换为 `\n` / `\r` 等。

#### 4.2 `parsePreheatBreakpoints(prop: String?): List<RenderedBreakpoint>`

解析 Gradle property `ideDebuggerPreheatBreakpoints`, 格式:
```
src=MainActivity.kt:10:5;src=Foo.kt:20:0;src=Bar.kt:30:1
```

每个 entry 是 `src=<file>:<line>:<column>`, 用 `;` 分隔 entry, 用 `:` 分隔
file/line/column。column=0 表示不指定列 (按整行匹配)。

**限制**:
- `<file>` 不能含 `;` 或 `:` (Android source file 一般没有)
- `<line>` / `<column>` 必须是非负整数
- 违反限制时抛 `IllegalArgumentException`, plugin 捕获 + log warn, degrade
  到空 `PREHEAT_BREAKPOINTS` (不阻塞 build)

返回空列表如果 prop 是 null 或空。

#### 4.3 `computeLocalServerName(project: Project): String`

子项目 9d 已有, 保持不变: `"ide-debug-bridge-${group}-${name}"` (group/name
为空时回退到默认值)。

#### 4.4 `HostAttachAgentBootstrap.startReverseConnectThread(application, name)`

把子项目 9c 现有的 `startBridgeThread(Context, String)` **重命名**为
`startReverseConnectThread` + 改 public + 改第一个参数为 `Application`
(更类型安全, 跟 `Application.onCreate` 入口对应):

**重命名动机**: 旧名 `startBridgeThread` 含义模糊 (桥接什么? 启动什么?),
新名 `startReverseConnectThread` 明确表达"启动反连线程", 跟 host 端
runtime 的设计一致 (host → IDE 是 reverse direction, 跟 IDE → host 不同)。

```java
// ide-debugger-host/.../HostAttachAgentBootstrap.java
public static void startReverseConnectThread(Application app, String socketName) {
    // 现有 startBridgeThread 逻辑:
    // 1) 启后台线程
    // 2) new LocalSocket().connect(LocalSocketAddress(name, ABSTRACT_NAMESPACE))
    // 3) 写 HELLO 行: "HELLO pkg=<pkg> pid=<pid> buildTs=<ms>\n"
    // 4) openLocalAbstractJdwpSocket() 拿 jdwp socket
    // 5) HostAttachAgentBridge.bridge(ideSocket, jdwpSocket)
    // 6) 失败 log warn, 不抛
}
```

幂等性: 调用者 (`IdeDebuggerBootstrap.init`) 用 `AtomicBoolean` 保护, 多次
调只起一次 thread。ContentProvider 路径走独立保护 (子项目 9c 已有)。

### 5. host app 集成示例

```kotlin
// host app 的 Application.kt
class MyApp : Application() {
    override fun onCreate() {
        super.onCreate()
        // 显式 init (与 ContentProvider 自动反连互补, 幂等)
        IdeDebuggerBootstrap.init(this)
        // 验证 IDE 端代码新鲜度 (可选)
        Log.i("MyApp", "IDE debugger buildTs=${IdeDebuggerBootstrap.BUILD_TIMESTAMP_MS}")
    }
```

### 7. 错误处理

| 失败场景 | 行为 |
|---------|------|
| plugin 写 .kt 失败 (IO / 权限) | logger.warn, 不抛; host app 拿不到 `IdeDebuggerBootstrap`, 编译期报错 (显式) |
| `ideDebuggerPreheatBreakpoints` 格式错 | parsePreheatBreakpoints 抛 IAE, plugin 捕获 + log warn, 生成空 PREHEAT_BREAKPOINTS (degrade) |
| `HostAttachAgentBootstrap.startReverseConnectThread` 内部失败 | log warn, 不抛, host app 正常启动 |
| ContentProvider + init() 同时跑 | 通过 `initialized` AtomicBoolean 幂等, 只起一个反连 thread |
| `escapeKtStringLiteral` 输入含 ASCII 0 | 转义为 `\\u0000` (Kotlin 字符串支持) |
| `extras` 含换行 | 转义为 `\\n` (Kotlin 字符串字面量) |
| `ideVersion` 长度 > 10000 | 仍能转义, 但不期望 (BuildInfo.VERSION_NAME 应该 < 100 char) |

### 8. 范围限定 (YAGNI)

不做:
- BP 预热配置 UI (IDE 端给用户配置入口) -- 后续方案 B
- 完整 host SDK (多 init 函数 + 事件 hook) -- 后续方案 C
- KotlinPoet 依赖 (用字符串模板即可, 减少 plugin 体积)
- IDE 端 UI 验证 "buildTs 是否最新" -- 留给 host app 开发者 (他们看 log)
- 跨 module 的常量共享 -- PREHEAT_BREAKPOINTS 只在 host app 可见

后续可基于本子项目自然演进:
- 方案 B: IDE 端 project 设置面板 + `ideDebuggerPreheatBreakpoints` 解析
  + `PREHEAT_BREAKPOINTS` 填实际 bp
- 方案 C: 加 `initWithBreakpoints` / `initWithCustomJdwp` / `onBreakpoint`
  hook 等
