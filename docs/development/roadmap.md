# 产品方向与开发路线

## 1. 产品愿景

ZeroStudio 的长期目标是成为 Android 设备端完整的原生开发环境：用户可以在 Android 设备上管理真实项目、编辑源码、调用语言服务、执行 Gradle 构建、运行和调试应用，并使用终端与 Native 工具链。

产品竞争力应来自本机工具链整合、编辑体验、工程可维护性和设备端性能，而不是简单堆积功能入口。

## 2. 产品原则

1. 本机优先：核心编辑、项目管理和构建流程尽量在设备本地完成。
2. 工程真实：优先兼容真实 Gradle/Android 工程，不以演示项目替代工程能力。
3. 编辑器优先：编辑、索引、语法分析和语言服务应具备可扩展接口。
4. 原生体验：新 UI 采用 Compose Material 3，并针对手机、平板和折叠屏适配。
5. 可组合模块：能力按领域模块化，接口稳定、实现可替换。
6. 性能可度量：大项目、大文件、Native 构建和多任务场景必须有性能指标。
7. 透明可维护：第三方来源、构建配置、架构决策和测试状态可追踪。

## 3. 开发阶段

### Phase 0 — 架构与文档基线（当前优先级最高）

目标：先统一认知和约束，再进入大规模功能开发。

交付：
- 总体架构和分层依赖图。
- Gradle 模块职责地图。
- 技术栈与版本配置来源。
- ADR 与第三方集成登记。
- 开发流程、编码规范、测试标准。
- Compose 迁移规则与路线图。

完成条件：文档与当前 Gradle 配置核对一致；目标方向与当前实现明确区分；核心开发规则可以用于审查后续 PR。

### Phase 1 — 构建与工程稳定性

目标：建立可重复的构建和 CI 基线。

工作：
- 验证主工程及独立 composite builds。
- 核对 JDK、Gradle、AGP、Kotlin、SDK、NDK、CMake 的组合。
- 统一构建参数与依赖来源。
- 修复工作流的依赖下载、缓存、产物命名和上传问题。
- 建立可复现的构建失败报告。

完成条件：主 APK 和关键 Native/独立模块构建均有成功记录；失败可定位到明确模块和步骤。

### Phase 2 — 核心 API 与领域边界

目标：先稳定底层契约，再扩展 UI。

工作：
- 审查项目、编辑器、构建、终端、设备和调试 API。
- 区分 domain contract、platform adapter 和具体实现。
- 消除跨模块内部类依赖。
- 明确异步任务、取消、错误和资源关闭契约。

完成条件：核心模块有清晰 API 文档和依赖关系，新增功能可在不依赖页面实现的情况下开发与测试。

### Phase 3 — Compose UI 体系建设

目标：形成统一 Compose Material 3 页面和组件体系。

工作：
- 建立主题、颜色、排版、形状、间距和自适应布局规范。
- 按底层 UI 状态与 API、基础组件、复合组件、页面的顺序迁移。
- 页面使用单向数据流，业务任务不进入 Composable。
- 逐步替换历史 View/XML 页面，保留必要的平台互操作边界。

完成条件：迁移范围内不存在遗留传统 View/XML UI 实现；页面具备状态、导航、无障碍和测试覆盖证据。

### Phase 4 — 核心 IDE 工作流完善

目标：优先打通完整开发闭环。

工作：
- 项目导入与管理。
- 编辑器、语法分析、补全和语言服务。
- Gradle 构建、任务与产物。
- 设备部署、日志和调试。
- 终端与工具链环境。

完成条件：从打开真实工程到编辑、构建、安装、查看日志的主流程可在目标设备上验证。

### Phase 5 — 扩展能力与效率提升

目标：完善 AI、Git、MCP、预览、资源工具和插件能力。

原则：扩展能力不能破坏核心编辑/构建流程的稳定性；高风险工具操作必须显式授权。

### Phase 6 — 性能、兼容性与发布质量

目标：建立长期性能和兼容性工程。

指标类别：
- 冷启动与页面切换。
- 大型工程导入、索引和文件树响应。
- 大文件打开、编辑、语法分析与首屏渲染。
- Gradle 构建时间、峰值内存和失败率。
- Native 内存、JNI 开销和稳定性。
- 手机、平板、折叠屏及不同 Android 版本的适配。

所有性能结论必须记录设备、系统版本、工程规模、输入文件和测量方法。

## 4. 优先级规则

优先级顺序：

1. 构建阻断、崩溃、数据丢失和安全问题。
2. 核心 API 错误与模块边界问题。
3. 主开发闭环缺失或不可用。
4. 性能瓶颈与高频交互缺陷。
5. Compose 迁移与一致性。
6. 扩展功能和体验优化。

如果底层契约不稳定，不应通过增加页面或临时 UI 逻辑掩盖问题。

## 5. 里程碑管理

每项任务需记录：目标、涉及模块、前置依赖、代码变更、验证命令、CI 链接、风险和回滚方式。路线图是顺序与目标，不代表已完成状态；实际进度应由 issue/PR 和验证记录更新。
