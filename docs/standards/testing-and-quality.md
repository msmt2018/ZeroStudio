# 测试与质量门禁

## 1. 质量目标

ZeroStudio 的质量标准不仅是编译成功，还包括运行稳定性、数据正确性、响应速度、资源安全、兼容性和可维护性。

## 2. 测试分层

### 单元测试

覆盖纯 Kotlin/Java 领域逻辑、状态转换、解析、模型映射、配置和算法。测试应可重复，不依赖真实网络或设备。

### 模块集成测试

验证模块间公开 API、数据库/文件适配、进程协议、JNI 映射和依赖装配。测试边界应与模块职责对应。

### Android 仪器测试

验证 Android framework 交互、权限、生命周期、存储、输入法、窗口、Compose UI 和真实设备能力。

### Compose UI 测试

优先使用 semantics 和用户行为验证页面，不依赖内部 Composable 结构。覆盖空态、加载态、错误态、交互、无障碍和窗口尺寸变化。

### Native 测试

验证边界输入、内存管理、并发、错误返回、JNI 生命周期、ABI 和大文件场景。可用 sanitizer/静态分析的地方应纳入独立 Native 验证。

### 性能测试

性能结论必须基于可重复输入、固定设备/系统环境和明确指标。区分冷启动、热路径、解析耗时、渲染耗时、内存峰值和 I/O。

## 3. 关键场景

- 导入大型 Gradle 工程与构建同步。
- 打开大文件、滚动、编辑、增量解析和语法高亮。
- 语言服务器启动、请求、取消、崩溃恢复和关闭。
- Gradle 构建中断、网络失败、磁盘空间不足和进程异常。
- 终端进程退出、PTY 关闭和环境变量隔离。
- ADB USB/Wi-Fi 连接断开、重新配对和权限拒绝。
- Native 内存压力、并发访问和重复创建/释放。
- Compose 页面重组、旋转、窗口大小变化和导航返回。

## 4. 性能度量

按模块定义指标，不使用单一总耗时替代整个体验：

| 领域 | 建议指标 |
|---|---|
| 启动 | 冷启动、首帧、首个可交互时刻 |
| 项目 | 导入、同步、索引完成时间与峰值内存 |
| 编辑器 | 文件打开、首屏渲染、滚动帧时间、编辑延迟 |
| 语法分析 | 完整解析、增量解析、查询/捕获、调度等待 |
| 构建 | 配置阶段、任务执行、依赖解析和总耗时 |
| Native | 分配次数、峰值内存、JNI 调用成本 |
| UI | 帧时间、掉帧率、重组次数（用于诊断） |

测试报告记录设备型号、Android 版本、构建变体、commit、输入规模和测量方法。

## 5. CI 门禁

- 受影响模块编译必须通过。
- 相关单元测试必须通过。
- Native 改动必须执行对应 Native 编译和测试。
- 关键工作流应验证产物是否存在、大小合理且可下载。
- 失败日志应保留足够上下文。
- 网络仓库限流等基础设施失败应单独分类，必要时重试，但不得掩盖真实源码失败。

## 6. 缺陷处理

缺陷报告包括复现步骤、预期/实际行为、环境、日志、影响范围和回归测试。修复后应增加能稳定复现原问题的测试或验证脚本。

## 7. 完成状态定义

- Implemented：代码已修改。
- Compiled：对应构建成功。
- Unit-tested：相关单元测试通过。
- Integration-tested：模块集成验证通过。
- Device-verified：目标 Android 设备上完成验证。
- CI-verified：对应 CI 工作流成功。

这些状态不可互相替代。未执行的验证必须标记为未验证。
